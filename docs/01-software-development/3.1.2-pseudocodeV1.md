# Pseudocode

!!! info "What You Need to Know"

    You must be able to read, understand, create, and implement designs written in **pseudocode**.

## Purpose

**Pseudocode** is a way of designing an algorithm using structured English instead of a specific programming language.

It is not finished program code. It is a design that explains the logic clearly enough for a programmer to implement later.

At Higher, pseudocode is used to show:

- the main algorithm, also called the top-level design
- data flow in and out of modules
- refinements for modules that need more detail
- important loops, decisions, and calculations

## National 5 to Higher

At National 5, pseudocode often focuses on the steps needed to solve a problem.

At Higher, pseudocode needs to show more design detail. It should make clear how the solution is split into modules and what data moves between them.

| National 5 pseudocode | Higher pseudocode |
|---|---|
| Shows the steps in an algorithm | Shows the top-level design and refinements |
| May focus on one sequence of instructions | Is usually split into modules |
| May not show data flow | Should show `IN` and `OUT` data flow |
| Helps plan the logic | Helps plan procedures, functions, and parameters |

The key difference is that Higher pseudocode should show the structure of the solution, not just a list of instructions.

## Main Algorithm

The **main algorithm** shows the major steps of the solution.

It should list the main tasks in a logical order without adding every small programming detail.

For example:

```text
1 Get results
2 Calculate percentages
3 Find position of pupil with top mark
4 Display pupil with top mark
```

Each main step represents a module. In the final program, these modules could become procedures or functions.

## Adding Data Flow

At Higher, each main step should show the data it needs and the data it produces.

This is often shown with the pseudocode on the left and the data flow on the right.

Use:

- `IN` for data passed into a module
- `OUT` for data passed out of a module

| Pseudocode | Data flow |
|---|---|
| `1 Get results` | `OUT: pupilName(), prelimMark(), courseMark()` |
| `2 Calculate percentages` | `IN: prelimMark(), courseMark()`<br>`OUT: percentage()` |
| `3 Find position of pupil with top mark` | `IN: percentage()`<br>`OUT: topPosition` |
| `4 Display pupil with top mark` | `IN: pupilName(), percentage(), topPosition` |

The brackets in names such as `pupilName()` and `percentage()` show that they are arrays.

For more help deciding what should be `IN` or `OUT`, see [Data Flow In and Out](3.1.3-data-flow-in-out.md).

## Adding Refinements

A **refinement** breaks one main step into smaller steps.

You use a refinement when a main step is too broad and needs more detail before it could be implemented.

The numbering shows which main step is being refined.

```text
1 Get results

1.1 Open marks file
1.2 Start fixed loop for each pupil
1.3 Read pupil name into pupilName()
1.4 Read prelim mark into prelimMark()
1.5 Read course mark into courseMark()
1.6 End fixed loop
1.7 Close marks file
```

The main step says what the module does. The refinement explains how it does it.

You do not need to refine every main step. A step only needs refinement if it is complex or unclear.

## Complete Example

The pseudocode below designs a program that reads pupil marks from a file, calculates percentages, finds the top pupil, and displays the result.

First, the top-level design and data flow are shown.

| Pseudocode | Data flow |
|---|---|
| `1 Get results` | `OUT: pupilName(), prelimMark(), courseMark()` |
| `2 Calculate percentages` | `IN: prelimMark(), courseMark()`<br>`OUT: percentage()` |
| `3 Find position of pupil with top mark` | `IN: percentage()`<br>`OUT: topPosition` |
| `4 Display pupil with top mark` | `IN: pupilName(), percentage(), topPosition` |

Then, refinements are added for modules that need more detail.

```text
1.1 Open marks file
1.2 Start fixed loop for each pupil
1.3 Read pupil name into pupilName()
1.4 Read prelim mark into prelimMark()
1.5 Read course mark into courseMark()
1.6 End fixed loop
1.7 Close marks file

2.1 Start fixed loop for each pupil
2.2 Set percentage() to (prelimMark() + courseMark()) / 1.5
2.3 End fixed loop

3.1 Set topPosition to first position
3.2 Start fixed loop from second pupil
3.3 If percentage() is greater than percentage(topPosition) then
3.4     Set topPosition to current position
3.5 End if
3.6 End fixed loop

4.1 Display pupilName(topPosition), percentage(topPosition)
```

This is detailed enough for a programmer to implement, but it is still a design rather than finished code.

## How Much Detail is Enough?

Pseudocode should be clear enough to implement, but it does not need exact programming language syntax.

Suitable design pseudocode:

```text
3.3 If percentage() is greater than percentage(topPosition) then
```

Finished Python code:

```python
if percentage[counter] > percentage[top_position]:
```

At the design stage, the first version is enough because it clearly explains the decision being made.

## Common Mistakes

Avoid these mistakes in Higher pseudocode:

- writing vague steps such as `Process data`
- missing `IN` and `OUT` data flow
- refining a step with code that is too language-specific
- adding refinements that do not match the main algorithm numbering
- showing keyboard, screen, or file as data flow instead of variables or arrays

## Checklist

Good Higher pseudocode should:

- use clear module names
- show `IN` and `OUT` data flow
- number refinements to match the main algorithm
- include important loops, decisions, and calculations
- be detailed enough for a programmer to implement
- avoid becoming full program code too early

## Summary

Pseudocode is a design technique used to describe an algorithm without using a specific programming language.

At Higher, pseudocode should show the top-level design, data flow, and refinements. It should make clear what each module does, what data it needs, and what data it produces.

A good Higher pseudocode design should help another programmer understand how the solution will work before implementation begins.
