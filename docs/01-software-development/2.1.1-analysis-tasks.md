# Analysis Tasks

Use each scenario to identify the program's:

- purpose
- boundaries
- functional requirements, using the IPO model

### Task 1: Online Game Leaderboard

A server manages the weekly leaderboard for an online game.

**Player details**

- Each player must have a nickname between 6 and 15 characters long.
- Each player must have a profile image.
- A default silhouette image can be used if no profile image is provided.

**Data used by the system**

- Each week, the system reads player experience points and ranks from a text file.

**Processing carried out**

- Sort all players by experience score.
- Select the top 10 players for the leaderboard.
- Identify the three players whose experience score has improved the most during the week.
- The three most improved players do not need to appear in the top 10.

**Outputs produced**

- Output the nickname, experience score and profile image for the top 10 players.
- Output the nickname, experience score and profile image for the three most improved players.
- Store these outputs in separate text files.
- The text files are then used to generate an interactive graph and table on the game's website.

**Questions**

(a) State the purpose of this program.

(b) State two boundaries of the program.

(c) Identify the functional requirements for the program, in terms of inputs, processes and outputs.

### Task 2: Supermarket Self-Scan System

A supermarket introduces a self-scan system that allows customers to use their smartphones while shopping.

**Data used by the system**

- Customers scan a QR code on each item.
- The system matches the QR code to a text file.
- The text file contains item names, prices and any discounts available that week.

**Processing carried out**

- Add the price of each scanned item to the customer's running total.
- Apply any discounts automatically when the customer reaches the checkout.
- Generate an itemised bill.
- Generate a final payment total.

**Outputs produced**

- Send the itemised bill to the customer.
- Send the itemised bill to the store.
- Send the final payment total to the customer.
- Send the final payment total to the store.
- The final payment amount can then be used to charge the customer's debit card.

**Questions**

(a) State the purpose of this program.

(b) State two boundaries of the program.

(c) Identify the functional requirements for the program, in terms of inputs, processes and outputs.

### Task 3: Cinema Ticket Booking System

A cinema introduces an online booking system that allows customers to reserve seats for film screenings.

**Booking details**

- Customers choose a film, screening time and seat.
- Customers enter their name and email address.
- Customers select the number and type of tickets required.

**Data used by the system**

- The system reads film titles, screening times, ticket prices and available seats from a database.
- The system checks whether the selected seats are still available.

**Processing carried out**

- Calculate the total cost of the selected tickets.
- Mark the selected seats as reserved.
- Generate a booking reference.
- Store the booking details.

**Outputs produced**

- Display a booking confirmation message.
- Display the booking reference.
- Send the booking details to the customer by email.
- Update the list of available seats for the screening.

**Questions**

(a) State the purpose of this program.

(b) State two boundaries of the program.

(c) Identify the functional requirements for the program, in terms of inputs, processes and outputs.

### Task 4: Fitness Class Attendance System

A leisure centre uses a system to record attendance at weekly fitness classes.

**Class details**

- Staff select the class name and date.
- Staff enter the names of members who attend.
- Each class has a maximum number of spaces available.

**Data used by the system**

- The system reads class names, dates and maximum class sizes from a text file.
- The system reads existing member details from a member database.

**Processing carried out**

- Check that each entered member exists in the member database.
- Count the number of members attending each class.
- Compare the attendance count with the maximum class size.
- Store the attendance record for the selected class.

**Outputs produced**

- Display the number of members who attended.
- Display a warning if the class is over capacity.
- Output an attendance list for staff.
- Save the updated attendance record.

**Questions**

(a) State the purpose of this program.

(b) State two boundaries of the program.

(c) Identify the functional requirements for the program, in terms of inputs, processes and outputs.
