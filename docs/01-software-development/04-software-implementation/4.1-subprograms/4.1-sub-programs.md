# Planning with Sub-programs

!!! info "What you need to know"

    You must be able to explain why programs are divided into sub-programs and
    identify each sub-program by its **name**, **inputs** and **outputs**.

A **sub-program** is a named section of a program that performs one clear task.
Breaking a large problem into smaller sub-programs is called **modular design**.

## Why Use Sub-programs?

Sub-programs can make a program:

- easier to understand because each part has one purpose
- easier to test because each part can be checked separately
- easier to maintain because a change can be made in one place
- easier to reuse because the same sub-program can be called more than once
- easier to develop as a team because different programmers can work on
  different modules

## From a Problem to Modules

Consider a program that calculates and displays a pupil's percentage.
It can be divided into three stages:

```text
1. Get the pupil's details and marks
2. Calculate the percentage
3. Display the result
```

This is a **top-level design**. Each line describes a module without yet showing
the detailed algorithm.

Good module names begin with a verb and clearly describe the task:

| Unclear name | Clearer name |
|---|---|
| `details` | `get_pupil_details` |
| `percentage` | `calculate_percentage` |
| `screen` | `display_result` |

## Inputs and Outputs

Before implementing a module, identify the data that crosses its boundary:

- an **input** is data the module needs
- an **output** is data the module produces for another part of the program

```text
Calculate percentage
IN: mark, total
OUT: percentage
```

The calculation also creates temporary values, but only data that crosses the
module boundary is listed as an input or output.

## Procedures and Functions

There are two kinds of sub-program at Higher:

- A **procedure** performs an action. For example, it might display a result.
- A **function** calculates and returns a value to the caller.

At this stage, concentrate on each module's purpose and data flow. The next
lesson shows how procedures, functions, parameters and return values are
implemented in Python.
