# The Fetch–Execute Cycle

!!! info "What you need to know"

    **Describe the stages of the fetch–execute cycle and the roles of the processor, registers, buses and main memory.**

A program is stored in main memory as a sequence of instructions. The processor retrieves and processes one instruction at a time using the **fetch–execute cycle**.

The cycle has three main stages:

1. **Fetch** the next instruction from memory.
2. **Decode** the instruction to determine what operation is required.
3. **Execute** the instruction.

The cycle repeats until the program ends or the processor is interrupted.

## Fetch

During the fetch stage:

1. The **program counter (PC)** holds the address of the next instruction.
2. The processor places this address on the **address bus**.
3. The control unit sends a **read** signal on the **control bus**.
4. Memory sends the instruction to the processor on the **data bus**.
5. The instruction is copied into the **instruction register (IR)**.
6. The program counter is updated so it refers to the next instruction.

## Decode

The control unit examines the instruction in the instruction register. It identifies the operation to perform and any data or memory address required.

## Execute

The processor carries out the decoded instruction. This might involve:

- performing a calculation or comparison in the ALU;
- moving data between registers and memory;
- reading input or producing output; or
- changing the program counter to branch to another instruction.

The result may be stored in a register or written to memory before the next cycle begins.

!!! example "A simple fetch"

    Suppose the program counter contains address ==1023==.

    The processor places ==1023== on the address bus and sends a read signal. Memory returns the instruction stored at that address on the data bus. The instruction is placed in the instruction register, decoded and executed. The processor then begins fetching the next instruction.

!!! note "Real processors"

    Modern processors can overlap stages and process several instructions at once using techniques such as pipelining. The fetch–decode–execute model still explains the purpose of the cycle.
