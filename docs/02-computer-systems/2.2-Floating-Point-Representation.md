# Representing Floating-Point Numbers

!!! info "What you need to know"

    **Describe and exemplify how positive and negative real numbers are stored using a mantissa and an exponent.**

    **Describe how the number of bits allocated to the mantissa and exponent affects precision and range.**

## Why floating point is used

An **integer** is a whole number, such as ==25== or ==-8==. A **real number** can contain a fractional part, such as ==4.75== or ==0.001==.

Computers use **floating-point representation** to store very large, very small and fractional real numbers. It works like scientific notation, but uses powers of 2 instead of powers of 10.

For example, the binary number **100.01** can be written as:

**0.10001 × 2<sup>3</sup>**

This means:

* **0.10001** stores the significant bits of the number
* **2<sup>3</sup>** shows that the binary point has moved **3 places**

In floating-point representation, the value is split into two parts:

| Part | Purpose |
|------|---------|
| **Mantissa** | Stores the significant bits of the number and its sign |
| **Exponent** | Stores how far the binary point has moved |

!!! note "The binary point"

    A binary point works like a decimal point, but it separates whole and fractional binary place values.

## The mantissa, exponent and normalisation

At Higher, the mantissa and exponent are stored slightly differently.

The mantissa uses a sign bit:

* ==0== for a positive number
* ==1== for a negative number

The exponent is stored using **two's complement**, so it can represent positive and negative movements of the binary point.

Before a number is stored, move the binary point so that the mantissa begins ==.1==. This is called **normalising** the number.

The sign bit and the exponent answer different questions. Do not mix them up.

| To decide the mantissa sign bit | Result |
|---------------------------------|--------|
| No minus sign | Use ==0== at the start of the mantissa |
| Minus sign | Use ==1== at the start of the mantissa |

| To decide the exponent | Result |
|------------------------|--------|
| Number is bigger than 1, so the binary point moves left | Positive exponent |
| Number is smaller than 1, so the binary point moves right | Negative exponent |

!!! note "Normalising and reading back"

    When you are **normalising** the original number, moving the binary point right gives a negative exponent.

    When you are **reading the stored number back**, a negative exponent moves the binary point left again.

    This is because reading it back reverses the normalising step.

!!! example "Example 1: binary point moves left"

    Convert the positive number 100.001101 using a 16-bit mantissa and an 8-bit exponent.

    The first ==1== in 100.001101 is part of the original number. It is **not** the mantissa sign bit yet.

    **Step 1: Normalise the number**

    As it is a positive number, normalise it so the mantissa begins ==.1==.

    Move the binary point 3 places left:

    100.001101 becomes .100001101 × 2<sup>3</sup>

    You now add a ==0== to show it is positive.

    .100001101 becomes 0.100001101

    As the binary point moved 3 places to the left, the exponent is therefore **+3**.

    0.100001101 × 2<sup>3</sup>

    **Step 2: Store the mantissa**

    Add zeros on the right until the mantissa contains 16 bits:

    0.100001101000000

    The binary point is not stored, so the stored mantissa is the remaining bits with a ==0== at the start because it is a positive number:

    ==0100 0011 0100 0000==

    **Step 3: Store the exponent**

    Write +3 in 8-bit binary:

    ==0000 0011==

    | Mantissa | Exponent |
    |----------|----------|
    | ==0100 0011 0100 0000== | ==0000 0011== |

## Reading the stored mantissa

Once the mantissa has been stored, the binary point is **not stored** as one of the bits.

It is **assumed** because its position is always known. This saves space because the computer only needs to store the bits, not the point itself.

When reading the stored mantissa back, place the binary point **between the first bit and the second bit**.

This is only the fixed reading position for the stored mantissa. It is **not** the same as moving the original binary point left or right when normalising.

For example, the stored mantissa from Example 1 is:

==0100 0011 0100 0000==

This can be split up as:

| First bit | Assumed binary point | Remaining bits |
|-----------|----------------------|----------------|
| ==0== | ==.== | ==100001101000000== |

So it is read as:

**0.100001101000000**

!!! example "Example 2: positive number less than 1"

    Convert the positive number 0.001010101 using a 16-bit mantissa and an 8-bit exponent.

    This number is positive because there is no minus sign. It is less than 1 because it starts with ==0.==.

    This is like a denary number such as ==0.8==: it is positive, but it is still less than 1.

    The exponent will be negative because the binary point needs to move right to normalise the number.

    **Step 1: Normalise the number**

    As it is a positive number, normalise it so the mantissa begins ==.1==.

    Move the binary point 2 places right:

    0.001010101 becomes .1010101 × 2<sup>-2</sup>

    You now add a ==0== to show it is positive.

    .1010101 becomes 0.1010101

    The number is still positive, but the exponent is **-2** because the binary point moved 2 places to the right.

    0.1010101 × 2<sup>-2</sup>

    **Step 2: Store the mantissa**

    Add zeros on the right until the mantissa contains 16 bits:

    0.101010100000000

    The binary point is not stored, so the stored mantissa is the remaining bits with a ==0== at the start because it is a positive number:

    ==0101 0101 0000 0000==

    **Step 3: Store the exponent**

    Store -2 as 8-bit two's complement:

    ==1111 1110==

    | Mantissa | Exponent |
    |----------|----------|
    | ==0101 0101 0000 0000== | ==1111 1110== |

## Representing a negative number

For a negative value, first normalise the positive magnitude. Then put a ==1== sign bit at the start of the mantissa to show that the number is negative.

!!! warning "Common misconception"

    The mantissa is **not** converted using two's complement at Higher.

    The exponent is stored using two's complement. The mantissa uses a sign bit.

!!! example "Example 3: negative number"

    Convert -1000.00001 using a 16-bit mantissa and an 8-bit exponent.

    This number is negative, but its size is bigger than 1.

    The binary point will move left because of the size of the number.

    The negative sign is shown separately using the mantissa sign bit.

    **Step 1: Normalise the positive magnitude**

    Ignore the minus sign temporarily and normalise the positive magnitude so the mantissa begins ==.1==.

    Move the binary point 4 places left:

    1000.00001 becomes .100000001 × 2<sup>4</sup>

    The original number was negative, so put a ==1== at the start of the mantissa to show it is negative.

    As the binary point moved 4 places to the left, the exponent is therefore **+4**.

    The normalised magnitude is:

    .100000001 × 2<sup>4</sup>

    The stored mantissa will start with ==1== because the original number was negative.

    **Step 2: Store the mantissa**

    Add zeros on the right until the mantissa contains 16 bits:

    1.100000001000000

    The binary point is not stored, so the stored mantissa is the remaining bits with a ==1== at the start because it is a negative number:

    ==1100 0000 0100 0000==

    **Step 3: Store the exponent**

    Write +4 in 8-bit binary:

    ==0000 0100==

    | Mantissa | Exponent |
    |----------|----------|
    | ==1100 0000 0100 0000== | ==0000 0100== |

## More worked examples

The same method works for whole numbers, fractions and negative values. Always normalise first, then store the mantissa and exponent.

!!! example "Example 4: positive mixed number"

    Convert the positive number 1.01 using a 16-bit mantissa and an 8-bit exponent.

    The first ==1== in 1.01 is part of the original number. It is **not** the mantissa sign bit yet.

    **Step 1: Normalise the number**

    As it is a positive number, normalise it so the mantissa begins ==.1==.

    Move the binary point 1 place left:

    1.01 becomes .101 × 2<sup>1</sup>

    You now add a ==0== to show it is positive.

    .101 becomes 0.101

    As the binary point moved 1 place to the left, the exponent is therefore **+1**.

    0.101 × 2<sup>1</sup>

    **Step 2: Store the mantissa**

    Add zeros on the right until the mantissa contains 16 bits:

    0.101000000000000

    The binary point is not stored, so the stored mantissa is the remaining bits with a ==0== at the start because it is a positive number:

    ==0101 0000 0000 0000==

    **Step 3: Store the exponent**

    Write +1 in 8-bit binary:

    ==0000 0001==

    | Mantissa | Exponent |
    |----------|----------|
    | ==0101 0000 0000 0000== | ==0000 0001== |

!!! example "Example 5: small positive fraction"

    Convert the positive number 0.0001101 using a 16-bit mantissa and an 8-bit exponent.

    **Step 1: Normalise the number**

    As it is a positive number, normalise it so the mantissa begins ==.1==.

    Move the binary point 3 places right:

    0.0001101 becomes .1101 × 2<sup>-3</sup>

    You now add a ==0== to show it is positive.

    .1101 becomes 0.1101

    As the binary point moved 3 places to the right, the exponent is therefore **-3**.

    0.1101 × 2<sup>-3</sup>

    **Step 2: Store the mantissa**

    Add zeros on the right until the mantissa contains 16 bits, including the sign bit:

    0.110100000000000

    The binary point is not stored, so the stored mantissa is the remaining bits with a ==0== at the start because it is a positive number:

    ==0110 1000 0000 0000==

    **Step 3: Store the exponent**

    Write -3 as 8-bit two's complement:

    | Step | Exponent |
    |------|----------|
    | +3 | ==0000 0011== |
    | Flip all bits | ==1111 1100== |
    | Add 1 | ==1111 1101== |

    | Mantissa | Exponent |
    |----------|----------|
    | ==0110 1000 0000 0000== | ==1111 1101== |

!!! example "Example 6: negative fraction"

    Convert -0.01101 using a 16-bit mantissa and an 8-bit exponent.

    **Step 1: Normalise the positive magnitude**

    Ignore the minus sign temporarily and normalise the positive magnitude so the mantissa begins ==.1==.

    Move the binary point 1 place right:

    0.01101 becomes .1101 × 2<sup>-1</sup>

    The original number was negative, so put a ==1== at the start of the mantissa to show it is negative.

    As the binary point moved 1 place to the right, the exponent is therefore **-1**.

    The normalised magnitude is:

    .1101 × 2<sup>-1</sup>

    The stored mantissa will start with ==1== because the original number was negative.

    **Step 2: Store the mantissa**

    Add zeros on the right until the mantissa contains 16 bits, including the sign bit:

    1.110100000000000

    The binary point is not stored, so the stored mantissa is the remaining bits with a ==1== at the start because it is a negative number:

    ==1110 1000 0000 0000==

    **Step 3: Store the exponent**

    Store -1 as 8-bit two's complement:

    ==1111 1111==

    | Mantissa | Exponent |
    |----------|----------|
    | ==1110 1000 0000 0000== | ==1111 1111== |

!!! example "Example 7: reading a stored floating-point number"

    A number is stored using:

    | Mantissa | Exponent |
    |----------|----------|
    | ==0100 1100 0000 0000== | ==0000 0010== |

    The mantissa is positive because it begins with ==0==.

    Put the assumed binary point between the first bit and the second bit:

    0.100110000000000

    The exponent is ==0000 0010==, which is **+2**.

    Move the binary point 2 places right:

    0.100110000000000 × 2<sup>2</sup> = 10.011

    So the stored value is:

    **10.011**

## A method to remember

1. Ignore the minus sign temporarily and normalise the positive magnitude to begin ==.1==.
2. Count how many places the binary point moved.
3. Add the sign bit at the start of the mantissa: ==0== for positive, ==1== for negative.
4. Pad the mantissa on the right to the required length.
5. Store the movement as the exponent. If the exponent is negative, use two's complement.

!!! tip "Exam tip"

    Keep the mantissa and exponent separate, and check their bit lengths before giving your final answer.

## Range and precision

A fixed number of bits is shared between the mantissa and the exponent.

### Range

**Range** means the spread between the smallest and largest magnitudes that can be represented.

The exponent controls range because it controls how far the binary point can move.

* More exponent bits give a **greater range**.
* Fewer exponent bits give a **smaller range**.

### Precision

**Precision** means how accurately a value can be represented.

The mantissa controls precision because it stores the significant bits of the value.

* More mantissa bits give **greater precision**.
* Fewer mantissa bits give **less precision**, so more rounding may be required.

!!! example "Precision example"

    Imagine that only four significant mantissa bits are available.

    The value 0.1011011 cannot be stored exactly because it contains too many significant bits. Some bits must be removed and the stored value must be rounded.

    With more mantissa bits, more of the original value could be kept.

| Change | Effect |
|--------|--------|
| Increase exponent bits | Increase range |
| Decrease exponent bits | Decrease range |
| Increase mantissa bits | Increase precision |
| Decrease mantissa bits | Decrease precision |

!!! warning "Do not mix these up"

    **Exponent = range**

    **Mantissa = precision**

    If the total number of bits is fixed, giving more bits to one part leaves fewer bits for the other. This creates a trade-off between range and precision.
